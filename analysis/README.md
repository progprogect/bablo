# Аналитика журнала сделок

Офлайн-анализ закрытых сделок: что отличает тейки от стопов и что спасло бы стопы.
Работает с **локальной выгрузкой CSV** — боевая база при этом не нужна и не трогается.

## Шаг 1. Выгрузить данные

На машине, где есть доступ к боевой БД, — одной командой:

```bash
./scripts/pull-journal-data.sh
```

Скрипт сам найдёт строку подключения (или спросит её), проверит связь, выгрузит
данные в `data/raw/` и предложит закоммитить их в текущую ветку.

Если нужен только экспорт, без обвязки:

```bash
export DATABASE_URL='postgres://...'        # Railway -> Postgres -> Variables
./scripts/export-journal-data.sh            # положит CSV в data/raw/
```

**Важно про строку подключения.** Снаружи Railway нужен `DATABASE_PUBLIC_URL`:
обычный `DATABASE_URL` указывает на внутренний хост `*.railway.internal`, который
с локальной машины не резолвится. `pull-journal-data.sh` это проверяет и говорит
об этом прямо, а не падает с невнятной ошибкой DNS.

Скрипт **только читает**. Гарантия не на словах: сессия открывается с
`default_transaction_read_only=on`, то есть любую попытку записи отклонит сам
PostgreSQL. Таблица `settings` (ключи BingX, PIN, VAPID) не выгружается.

В конце печатается сводка по объёму — её полезно посмотреть сразу.

## Шаг 2. Прогнать анализ

```bash
pip3 install pandas numpy scipy scikit-learn

python3 analysis/profile_data.py   data/raw   # что вообще есть в данных
python3 analysis/discriminate.py   data/raw   # что отличает тейки от стопов
python3 analysis/counterfactual.py data/raw   # что спасло бы стопы
```

Начинать с `profile_data.py`: он показывает объём, покрытие свечами и снапшотами.
Если свечей нет — раздел «а если бы» работать не будет.

## Что внутри

| Файл | Назначение |
|---|---|
| `lib/load.py` | CSV → таблицы. Порт продуктовой логики исхода и геометрии входа |
| `lib/replay.py` | Движок реплея сделки по свечам |
| `lib/stats.py` | Размеры эффектов, FDR, перестановки, скан порогов, бутстрэп |
| `lib/test_replay.py` | Тесты движка и конвертации времени |
| `profile_data.py` | Полнота и качество выгрузки |
| `discriminate.py` | Поиск зависимостей «признаки → исход» |
| `counterfactual.py` | Сетка «шире стоп × ближе тейк», сдвиг входа, безубыток |
| `make_synthetic.py` | Синтетика с ЗАЛОЖЕННЫМ эффектом — проверка самого пайплайна |

Скрипты выгрузки — `scripts/pull-journal-data.sh` (обвязка) и
`scripts/export-journal-data.sh` (сам экспорт).

## Решения, которые важно понимать

**Геометрия входа восстанавливается, а не берётся из `sl_price`.** В `trades` лежит
ТЕКУЩИЙ стоп, подвинутый трейлинг-лестницей и ночным правилом. Исходный риск — это
`risk_usd / quantity` (порт `journal/logic.ts#entryRiskDistance`). Взять `sl_price`
напрямую означало бы считать риск по уже переставленному стопу.

**Исход берётся по экономике, а не по типу ордера.** Порт
`history/outcome.ts#resolveTradeOutcome`: стоп, закрывшийся в плюс, — это тейк.
Цифры совпадают со статистикой в приложении.

**Абсолютные ценовые уровни исключены из признаков.** `ema200`, `dayVwap`, `close` —
это цена BTC против цены ETH. В сравнении «тейки против стопов» такой признак покажет
красивую разницу, означающую лишь «символы разные». Остаются только нормированные
величины: проценты, отношения, доли ATR.

**Признаки разворачиваются по направлению сделки (`_dir`).** Перекупленность опасна
для лонга и безобидна для шорта. Без разворота эффекты лонгов и шортов взаимно
гасятся, и настоящая зависимость становится невидимой — это проверено на синтетике,
где заложенный эффект без разворота не находился.

**Поправка на множественные сравнения обязательна.** При ~95 признаках порог p<0.05
даёт около 5 «значимых» находок на чистом шуме. Поэтому везде FDR, а в скане порогов —
перестановочный порог по максимуму статистики (он выходит около |z|=3.8 вместо
наивного 1.96).

**Неопределённый исход — не победа.** Если свечей не хватило, сделка помечается
`undetermined` и в экспектацию не идёт. Молча считать такие сделки тейками — главный
способ нарисовать себе грааль.

**Контрфактическое правило применяется ко ВСЕМ сделкам.** Расширив стоп, легко
«спасти» половину стопов и незаметно испортить тейки. Смотреть только на проигравшие
= гарантированно получить стратегию, которая теряет деньги.

**База сравнения — тот же движок.** Вариант сравнивается не с фактической историей,
а с прогоном исходной геометрии через тот же реплей: иначе в «улучшение» попадёт
собственная погрешность движка. Насколько ему верить — показывает калибровка
(раздел 0 отчёта): доля реальных исходов, которые он воспроизводит.

## Проверка самого пайплайна

`make_synthetic.py` генерирует выгрузку в том же формате с одним намеренно
заложенным эффектом (чем дальше рынок уже прошёл в сторону сделки, тем хуже исход).

```bash
python3 analysis/make_synthetic.py /tmp/synth 600
python3 analysis/discriminate.py   /tmp/synth
```

На 600 сделках пайплайн находит именно заложенное семейство признаков и не находит
посторонних. На 120 — честно сообщает, что эффект неотличим от шума. Это и есть
проверка: инструмент обязан и находить настоящее, и молчать о ненастоящем.

```bash
python3 analysis/lib/test_replay.py   # тесты движка
```
